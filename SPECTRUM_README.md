# Axel Spectrum

Вариант с готовым загружаемым Python-скриптом доступен отдельно в `spectrum-analyzer-fixed.html`; инструкция — `SPECTRUM_FIXED_README.md`. В обеих версиях добавлены просмотр сохранённого JSON и сортировка/подписи по локальному контрасту. Вариант с генерацией скрипта также просит модель отбирать пики по превышению над фоном, чтобы низкочастотные амплитуды не вытесняли узкие линии.

Самостоятельный интерфейс в `spectrum-analyzer.html` для спектрального анализа TXT через OpenAI Responses API / Code Interpreter. Установка Python, MATLAB или npm для использования страницы не требуется. Страница не содержит готового расчётного Python-скрипта: модель создаёт и исполняет его в облаке при каждом анализе.

## Запуск

1. Откройте `spectrum-analyzer.html` в актуальном Edge или Chrome.
2. Выберите TXT. Поддерживаются Axel DTR (`[!DTR:80:+1-2+3...]`) и текст с одним числовым отсчётом на строку. Выберите соответствующий формат в форме. Зашифрованные `.log` не поддерживаются.
3. Задайте частоту дискретизации и диапазон поиска пиков. Для DTR модель должна сверить частоту с полями лога; несовпадение считается ошибкой данных.
4. Введите собственный OpenAI API key, модель и уровень reasoning. По умолчанию указаны `gpt-5.6-luna` и `medium`; нужна поддержка Code Interpreter и фоновых Responses-запросов. Параметр отправляется в API как `reasoning: { effort: "medium" }`.
5. Нажмите «Анализировать». TXT будет загружен в OpenAI; запрос модели и контейнер оплачиваются по тарифам вашего API-аккаунта. Не закрывайте вкладку до получения результата или завершения остановки.
6. Скачайте JSON, полный спектр CSV и Python-код. Кнопка «Пример результата» показывает только иллюстрацию интерфейса без сетевых запросов; у демонстрационного JSON есть `demo: true` и отдельное имя скачивания.

При сетевом/CORS-ограничении `file://` можно раздать эту же папку статическим HTTP-сервером, например `python -m http.server 8000 --bind 127.0.0.1`, если Python уже установлен, и открыть `http://127.0.0.1:8000/spectrum-analyzer.html`. Это только раздача HTML: расчёты по-прежнему выполняются в OpenAI. Если сеть блокирует OpenAI, HTTP-сервер не устраняет сетевой запрет.

## Результат

- `analysis.json`: статистика исходного сигнала, параметры анализа, пики, предполагаемые гармонические семейства, уменьшенный спектр для графика, заключение и ограничения на русском.
- `spectrum.csv`: полный односторонний спектр с колонками `frequency_hz,raw_amplitude,smoothed_amplitude`, включая частоты вне диапазона поиска пиков.
- `analysis.py`: созданный моделью расчётный скрипт для просмотра и воспроизведения методики.

Промпт закрепляет линейный detrend, симметричное окно Ханна, FFT без дополнения нулями, нормировку на сумму окна и удвоение положительных частот кроме DC и Найквиста. По умолчанию линейная амплитуда сглаживается гауссовым ядром FWHM=0.02 Гц, а более близкие максимумы объединяются; ширина меняется в настройках, 0 отключает сглаживание. Амплитуды указаны в исходных единицах, не в Па/бар без калибровки. `Fs/N` — шаг FFT, не доверительный интервал оценки частоты. По умолчанию временные окна: 8192 отсчёта, шаг 4096; короткие записи требуют уменьшения окна с отметкой в результате.

Уровень `reasoning.effort` выбирается в форме (`none`, `low`, `medium`, `high`, `xhigh`, `max`) и зависит от возможностей модели. Для `gpt-5.6-luna` поддерживаются все перечисленные значения; `medium` оставлен по умолчанию как баланс качества, задержки и стоимости.

Модель сама выбирает способ оценки локального фона и проверки гармонических семейств и должна объяснить эти решения. Метод может различаться между запусками. Это исследовательский вариант, не детерминированный сертифицированный измерительный алгоритм. Наличие гармоник не доказывает их происхождение от насоса или принадлежность к помехам. FIR-фильтр эта версия не рассчитывает.

Статусы JSON:

- `ok`: модель сформировала анализ без статуса сомнения.
- `needs_review`: результат требует дополнительной оценки.
- `invalid_input`: разбор входных данных невозможен или нарушены условия, например Fs не совпадает. В этом случае JSON и Python доступны, спектр CSV не требуется.

Страница проверяет структуру JSON, соответствие Fs и диапазона запросу, согласованность N/длительности/шага FFT, конечность чисел и ссылки семейств на пики. Она не выполняет независимое повторение численных расчётов. Успешный статус Responses API сам по себе не считается успешным анализом: нужны завершённый Code Interpreter и скачанные файлы. Если файл отсутствует или структура не согласована, допускается один дополнительный запрос модели для исправления и перепроверки; он тоже оплачивается API-аккаунтом.

## Данные, ограничения и остановка

Ключ вводится пользователем, не зашит в HTML, не передаётся модели, не записывается в localStorage/sessionStorage/cookies и не включается в скачанные файлы. Файл и настройки отправляются непосредственно на `https://api.openai.com/v1`. Внешних JS/CSS, CDN и аналитики нет. CSP ограничивает сетевые подключения доменом API. Ответы и имена файлов выводятся как текст, без исполнения HTML от модели.

Это персональный локальный инструмент с ключом в браузере, а не архитектура для публичного многопользовательского сайта. Не публикуйте заполненную копию страницы с ключом; для общего сервиса ключ нужно хранить на сервере. На хранение переданных данных на стороне OpenAI распространяются настройки вашего API-проекта.

Размер TXT ограничен приложением до 20 МБ; JSON/Python — до 8 МБ каждый, CSV — до 128 МБ. Контейнер создаётся с 1 ГБ памяти. Через 20 минут ожидания приложение пытается остановить фоновый ответ. GET может повторяться после временных HTTP-ошибок; запросы создания контейнера/ответа автоматически не повторяются, чтобы не дублировать оплачиваемую работу.

«Стоп» отменяет ожидание и отправляет отмену фонового ответа. Если POST ещё не вернул ID ресурса, приложение сначала ждёт его ответ, затем отменяет работу. После загрузки файлов, ошибки или отмены приложение удаляет созданный им контейнер. Локальные скачивания/копии результатов остаются доступными в открытой странице. При ошибке очистки появляется кнопка повтора в журнале. Закрытие/сбой браузера или потеря сети могут помешать отмене и очистке; контейнеры также имеют срок жизни на стороне API. Сохранённый Responses-ответ не удаляется этой страницей; `background: true` использует `store: true`.

Ошибки 401/403/429 отображаются с пояснениями и без API key. Проверьте ключ, доступ проекта к модели, баланс/квоты и разрешение фоновых запросов. При сетевой ошибке после создания ответа его состояние может быть неизвестно; новый запуск может создать второй оплачиваемый запрос.

## Проверка разработки

`qa/spectrum-analyzer.smoke.cjs` использует Playwright и установленный Microsoft Edge. Запуск: `node qa/spectrum-analyzer.smoke.cjs`. Требуется доступный модуль `playwright` (или bundled runtime Codex на машине разработки). Все запросы к OpenAI перехватываются тестом; настоящий ключ и платные вызовы не используются.

Проверяются успешный фоновый анализ и скачивание исходного JSON, ввод параметров/файлов, мобильная разметка, вкладки, безопасный вывод текста, отсутствие хранения ключа, ошибки 401/неполный ответ/отсутствие Python, одна попытка исправления JSON, отклонение частот вне диапазона, ошибочные данные, пустой список пиков, отмена во время создания/ожидания ответа и повтор очистки контейнера.

Живой запрос с настоящим API key не выполнялся. Отдельный запрос OPTIONS без ключа подтвердил CORS для `/v1/containers` с Origin `null`. Это проверка доступности браузерного транспорта, не проверка доступа к модели или научной корректности сгенерированного кода.
